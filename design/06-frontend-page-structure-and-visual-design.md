# 06. 正式前端页面结构与视觉方案

## 0. 文档定位

本文用于把当前 Medora 用户端前端从“阶段联调页”升级为“可演示的正式产品页面”。

本文解决的问题：

- 统一用户端页面结构、导航与核心信息架构
- 明确正式页面和联调页的边界
- 固定一套可实现的视觉语言、组件体系和内容风格
- 为下一步前端落地提供直接映射关系，避免再次出现“只跑接口、不像产品”的页面

本文不讨论后台管理页视觉重做，后台页继续以可观测性和运营效率优先。

---

## 1. 当前问题

当前用户端页面的主要问题：

1. 页面命名和内容明显以阶段开发为中心，而不是以患者任务为中心。
2. 登录、预约、聊天页面都是“接口联调台”结构，缺少统一导航、任务入口和品牌感。
3. 视觉层面过于朴素，页面之间缺少共同语言，无法作为作品集或演示站点使用。
4. 用户主路径没有被组织成连续体验：
   - 进入首页
   - 登录/注册
   - 找科室/医生/号源
   - 完成预约
   - 继续在导诊助手中追问

---

## 2. 设计目标

### 2.1 产品目标

- 让 Medora 看起来像一个真实可用的医疗服务产品，而不是调试控制台。
- 把最关键的两条主路径做顺：
  - 预约挂号路径
  - AI 导诊路径
- 保持当前后端真实接口不变，前端在既有 API 能力之上完成产品化包装。

### 2.2 体验目标

- 用户第一次进入首页，能够立即理解 Medora 的核心价值。
- 用户在预约中心中可以自然地完成：
  - 选科室
  - 看医生
  - 看号源
  - 创建预约
  - 查看和取消预约
- 用户在导诊页中感受到：
  - 这是一个医疗助手，不是裸聊天窗口
  - 能接住多轮问题
  - 能给出可继续行动的下一步

### 2.3 工程目标

- 尽量复用已有 API 和现有状态管理方式
- 不引入新的重型前端框架
- 优先通过页面结构、组件统一和视觉升级完成产品化

---

## 3. 视觉方向

## 3.1 整体风格

采用 `温暖医疗 + 编辑化信息设计` 方向。

关键词：

- calm
- clinical
- humane
- editorial
- trustworthy

不是：

- 冷冰冰的医院 HIS 风格
- 互联网运营风活动页风格
- 泛 AI 产品的霓虹紫渐变风格

## 3.2 记忆点

Medora 的记忆点应该是：

- 像一本“高可信医疗服务手册”一样清晰
- 有温度，但不过度可爱化
- 既能做严肃业务动作，也能承载对话式助手

## 3.3 色彩系统

主色系：

- `Forest Ink`：深墨绿，用于标题、主按钮、导航锚点
- `Ivory Paper`：偏暖白，用于页面底色
- `Sage Mist`：浅鼠尾草绿，用于辅助卡片与提示区
- `Clay Rose`：低饱和暖红，用于风险与提醒
- `Brass Glow`：少量黄铜金，用于强调数值、徽标与重要状态

建议色值：

- `--bg-root: #f6f1e8`
- `--bg-surface: #fffdf8`
- `--bg-soft: #edf3ee`
- `--ink-strong: #142a27`
- `--ink-body: #36514c`
- `--line-soft: #d9ddd4`
- `--accent-main: #1f5c52`
- `--accent-warm: #b88451`
- `--danger-soft: #f9ebe6`

## 3.4 字体策略

展示字体：

- 优先使用中式衬线气质字体栈
- 例如：`"Iowan Old Style", "Palatino Linotype", "Noto Serif SC", "Songti SC", "STSong", serif`

正文与 UI 字体：

- 使用更稳的中性人文无衬线栈
- 例如：`"PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", "Noto Sans CJK SC", sans-serif`

注意：

- 不使用 `Inter`
- 不使用 `Roboto`
- 不使用默认系统无差别风格作为主视觉

## 3.5 版式原则

- 首页采用编辑化大标题和不对称留白
- 功能页采用“任务区 + 结果区”双栏结构
- 卡片圆角偏大，但边框克制，不用玻璃拟态
- 使用大块留白和弱纹理背景提升质感

## 3.6 动效原则

- 页面首次进入使用轻量级淡入和上浮
- Hover 反馈以边框、阴影和位移为主
- 不做花哨粒子动画，不影响医疗产品的可信度

## 4. 用户端信息架构

## 4.1 一级导航

用户端正式导航统一为：

- 首页 `/`
- 预约中心 `/appointments`
- 导诊助手 `/chat`
- 登录/账户 `/login`

说明：

- 当前阶段不单独拆 `/departments` 或 `/doctors` 页面
- 科室、医生、号源浏览统一收敛进 `预约中心`

## 4.2 首页结构

首页不是接口入口页，而是产品入口页。

首页建议结构：

1. Hero
   - 产品价值说明
   - 两个主 CTA：
     - 立即预约
     - 开始导诊
2. 信任区
   - 真实业务能力说明
   - 知识库、预约、会话、可观测能力简述
3. 主路径区
   - 挂号路径
   - AI 导诊路径
4. 服务亮点区
   - 科室查询
   - 医生选择
   - 多轮连续对话
   - 预约状态追踪
5. 页脚

## 4.3 登录/账户页结构

登录页要兼顾未登录和已登录两种状态。

未登录：

- 登录卡片
- 注册卡片
- 产品说明侧栏

已登录：

- 当前账户信息
- 个人默认偏好
- 快捷入口：
  - 去预约中心
  - 去导诊助手
  - 刷新当前用户信息
  - 退出登录

## 4.4 预约中心页结构

预约中心承担“找资源 + 做动作”两个任务。

建议结构：

左侧筛选区：

- 日期
- 科室
- 医生
- 时段

中间主内容区：

- 科室卡片
- 医生列表
- 可预约号源卡片

右侧辅助区：

- 当前选择摘要
- 我的预约列表
- 创建预约结果反馈

## 4.5 导诊助手页结构

导诊助手不只是聊天窗，而是“会话工作台”。

建议结构：

左侧：

- 会话列表
- 新建会话
- 常用问题引导

中间：

- 当前会话消息流
- 引用卡片
- 工具状态提示

底部输入区：

- 多行输入框
- 发送按钮
- 快捷提问 chips

右侧辅助区（宽屏可见）：

- 助手能做什么
- 推荐追问
- 当前会话提示

## 5. 组件体系

本次正式化至少统一以下组件：

- `PatientShell`
- `TopNav`
- `PageHero`
- `SectionHeader`
- `PrimaryButton`
- `SecondaryButton`
- `StatusBanner`
- `SurfaceCard`
- `MetricCard`
- `FilterPanel`
- `TimelineList`
- `ChatBubble`
- `SourceCard`
- `EmptyState`

其中优先抽象：

- 页面壳层
- 按钮
- 卡片
- 状态条

这样可以在不引入复杂设计系统的前提下，先让页面拥有统一语言。

## 6. 页面与接口映射

## 6.1 首页 `/`

使用接口：

- 无强依赖

可选动态信息：

- 登录态存在时，显示“继续预约”与“继续上次会话”

## 6.2 登录/账户页 `/login`

使用接口：

- `POST /api/v1/auth/register`
- `POST /api/v1/auth/login`
- `POST /api/v1/auth/logout`
- `GET /api/v1/users/me`
- `PUT /api/v1/users/me`

## 6.3 预约中心 `/appointments`

使用接口：

- `GET /api/v1/departments`
- `GET /api/v1/doctors`
- `GET /api/v1/schedule-slots`
- `POST /api/v1/appointments`
- `GET /api/v1/appointments`
- `POST /api/v1/appointments/{appointmentId}/cancel`

## 6.4 导诊助手 `/chat`

使用接口：

- `GET /api/v1/chat/conversations`
- `POST /api/v1/chat/conversations`
- `GET /api/v1/chat/conversations/{conversationId}/messages`
- `POST /api/v1/chat/conversations/{conversationId}/stream`

## 7. 本轮落地范围

本轮按“文档后立即实现”的原则，落以下正式页面：

1. 首页 `/`
2. 登录/账户页 `/login`
3. 预约中心 `/appointments`
4. 导诊助手 `/chat`
5. 全局样式与用户端壳层组件

本轮不做：

- 用户端完整设置中心
- 医生详情独立页
- 复杂动画与高级图表
- 多语言切换

---

## 8. 页面落地优先级

### P0

- 全局样式升级
- 顶部导航和页面壳层
- 首页

### P1

- 登录/账户页
- 预约中心

### P2

- 导诊助手正式化

---

## 9. 验收标准

### 9.1 视觉层

- 用户端页面不再出现 `Phase X` 联调文案
- 页面之间拥有统一视觉语言
- 首页达到可展示作品集标准

### 9.2 结构层

- 一级导航清晰
- 用户能找到预约和导诊两个主任务入口
- 预约页不再只是“查号源按钮 + 列表”

### 9.3 工程层

- 保持现有接口联调能力
- `npm run build` 通过
- 不影响后台 `/admin` 页面

---

## 10. 实施说明

为控制风险，本轮采用“先立统一壳层，再替换页面内容”的方式：

1. 先重做全局样式和用户端壳层
2. 再重做首页
3. 再重做登录/账户页
4. 再重做预约中心
5. 最后重做导诊助手

这样做的好处：

- 页面风格统一
- 不容易写到一半又回到联调页气质
- 每一步都可以单独 `build` 验证
